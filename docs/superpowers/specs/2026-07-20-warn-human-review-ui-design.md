# Warn 人工复核页面修复设计

日期：2026-07-20

## 目标

把 Warn 人工复核恢复为与语义校准同属一个人工复核工作台的完整操作界面，并修复问题视频生成失败和内部异常泄露。页面必须让复核员按照“看视频、理解原因、做出判断”的顺序完成单个 Warn，而不是阅读未排版的机器字段。

## 已确认的视觉方向

页面采用纵向复核流，不使用左右问题列表与详情分栏：

1. 顶部上下文栏展示资产编号、当前 Warn 和问题进度。
2. 主区域顶部展示当前 Warn 的问题视频，问题帧范围和当前帧覆盖在视频区域内。
3. 视频下方展示“为什么进入人工复核”，只保留复核员需要理解的原因、关键指标、阈值和证据范围。
4. 最下方提供同等面积的 PASS 与 FAIL 主操作。PASS 表示误报或问题可接受，FAIL 表示确认存在问题。
5. 一次只展示一个 Warn。当前结果保存成功后更新进度，再进入下一项；最后一项完成后才允许结束 Warn 复核。

视觉系统沿用现有工作台的字体、间距、圆角、浅色表面和深色视频舞台。Warn 使用橙色作为任务与证据强调色，PASS 和 FAIL 分别使用克制的绿色与红色状态色。窄屏按原顺序堆叠，不改变操作顺序。

## 组件结构

### 问题视频

- 使用工作台现有视频元素，不创建第二个播放器。
- 优先播放生成的问题片段；片段不可用时回退到原视频并定位到问题起始帧。
- 视频区域显示问题帧范围和当前帧，不在正文暴露内部路径。
- 骨架类问题存在 overlay 时允许显示；普通视频类 Warn 播放原始问题片段。

### 进入复核原因

- 原因使用可读文本，不直接呈现原始 JSON。
- 指标与阈值组成一条可扫描的判断依据；复杂指标使用紧凑键值展示。
- 证据范围使用面向复核员的闭区间帧号，同时保留内部半开区间语义。

### 人工判定

- PASS 与 FAIL 是页面唯一主操作。
- 可选判定原因放在判定区内，但弱于两个主按钮。
- 保存中禁用重复操作；保存失败时保留当前 Warn 和输入内容。
- 完成状态由服务端 revision 和 issue review 结果决定，不引入本地持久化。

## 数据与错误处理

`EvidenceService` 继续负责按需生成问题片段。原子临时文件必须保留最终媒体扩展名，或显式指定 FFmpeg 输出容器，确保 FFmpeg 能识别 MP4。

服务端任务 DTO 不得返回命令行、绝对路径或 Python 异常原文。证据失败只向前端提供稳定的错误类别和面向复核员的提示。前端区分“问题片段不可用”和“overlay 不可用”，不能把所有证据错误写成 overlay 失败。

证据降级不阻断人工判定：片段失败时尝试原视频定位；overlay 失败时继续播放问题片段。只有视频与原始视频都不可访问时才显示阻断性提示。

## 测试与验收

自动化测试覆盖：

- Warn 页面所需的布局、视频徽标、原因区、判定区和响应式选择器存在。
- 机器字段保持只读，PASS/FAIL 仍是唯一判定写入口。
- FFmpeg 临时输出具有可识别的 MP4 格式，回归测试必须先复现原 `.tmp` 失败。
- 服务端不向任务 DTO 暴露命令、绝对路径或异常原文。
- 片段失败与 overlay 失败在前端显示不同的安全提示。

浏览器验收覆盖桌面和窄屏：视频在上，原因与证据居中，PASS/FAIL 在下；不存在原生未样式化控件、横向溢出或整段命令错误。最终在本地工作台使用真实生成的视频片段完成一次 Warn 切换和判定交互。

## 范围边界

本次不重做语义校准页面，不改变 Warn 选样规则、报告 schema 或服务端 Pass/Fail 业务语义，也不引入新的前端框架。修复仅落在 Warn 展示、证据生成、错误投影和对应测试、文档。
